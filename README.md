# WakeLock

Android 8.0（API 26）以降向けの、曜日別アラームとQR認証を組み合わせた目覚ましです。v2では2枚のQRを時間を空けて合計4回読み取ります。最後に洗面所へ戻ってQRを読んだ時点で、その朝の起床プロトコルが完了します。

window794が「自分にはこれが便利だ」と思って作りましたが、あなたの布団に勝てるかは未検証です。

旧版では、布団に戻ってからでも再確認のボタンを押すだけで完了できました。v2は朝の生活行動への移行を促すため、10分後とさらに5分後にもう一度移動する機会を作ります。記録するのは指定のQRを読み取った事実です。覚醒状態の医学的評価は行いません。Kotlin、Jetpack Compose / Material 3、AlarmManager、CameraX、ML Kit、Preferences DataStoreを使用しています。

WakeLock is a personal Android project developed with the assistance of OpenAI Codex. Requirements, design decisions, and testing are reviewed by the project owner.

## ビルドとインストール

このフォルダがGradleプロジェクトのルートです。Android Studioでは **Open** で `wakelock-android` を選択します。VS CodeやPowerShellでも同じGradle Wrapperが使えます。

v0.5.0はライト・ダーク両対応のMaterial 3 UIを採用しています。クローン後に `git switch feature/material3-redesign` でこの版に切り替えます。

このPCで検出した環境はWindows、Android Studio付属のJBR 25.0.3、Android SDK Platform 37.0、Build Tools 36.0.0です。プロジェクトではGradle 9.6.0、Android Gradle Plugin 9.4.1、組み込みKotlinとComposeコンパイラー2.2.10、Javaバイトコード17を使います。minSdkは26、compileSdkとtargetSdkは37です。

1. 別のPCではAndroid StudioのSDK ManagerなどでAndroid SDK Platform 37、Build Tools 36.0.0、Platform-Toolsをインストールします。JDKはAndroid Studio付属のJBRが利用できます。
2. クローンした `wakelock-android` の親フォルダから以下を実行します。すでにリポジトリのルートにいる場合は2行目から実行してください。JBRやSDKを別の場所に入れた場合はパスを読み替えてください。初回ビルドには依存関係取得用のネットワーク接続が必要です。

```powershell
cd wakelock-android
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

デバッグAPKの出力先は `app\build\outputs\apk\debug\app-debug.apk` です。実機で開発者向けオプションとUSBデバッグを有効にし、PCの接続を端末で許可してインストールします。

```powershell
& "$env:ANDROID_HOME\platform-tools\adb.exe" devices
.\gradlew.bat :app:installDebug
```

## v0.5.0の画面

下部のタブから「アラーム」「履歴」「QRコード」「設定」を開けます。ホームの準備状況をタップすると、不足しているQRや権限の画面に移動します。起床中は「洗面所へ」（水滴・青）と「キッチンへ」（カップ・オレンジ）で、今向かう場所を示します。下部の「QRを読み取る」でカメラが開き、対象と違うQRを映しても同じ画面で読み直せます。緊急停止には確認が必要です。

QRの最終読み取りは、その場所の認証時刻が履歴にある場合に表示します。発行日時は保存していません。印刷は既存の1地点1ページ、スヌーズは全アラーム共通の5分×1回です。オフの単発カードで次回日時が未設定の場合は「1回のみ」と表示します。

## 最初のアラームを設定する

1. 下部の「QRコード」タブで、洗面所とキッチンをそれぞれ選びます。初めてなら「QRを作成」でその地点に自動登録されます。以前に作ったQRを初めて登録する場合は「カメラで登録」で読み取ります。
2. 両地点が「登録済み」になったら「表示・印刷」から印刷し、それぞれの場所に設置します。以前から貼ってある登録済みのQRはそのまま使えます。生成はZXing Core、読み取りはCameraXと同梱のML Kitを使用し、どちらも端末内で完結します。
3. 「設定」タブの「権限」で正確なアラーム・通知・ロック画面の全画面通知を確認します。同じタブの「初期のアラーム音」「端末のアラーム音量」で、新しく作るアラームの初期音と端末音量を確認できます。
4. 一覧右下の「＋」を押し、数字入力または時計盤で時刻を選び、右上の「保存」を押します。両地点が登録済みならそのままオンになります。未登録ならオフで作成されるので、QR登録後にスイッチを入れてください。
5. 鳴動したら画面または通知から読み取りを開き、洗面所 → キッチンの順に認証します。2地点目まで音と振動を継続します。カメラが使えない場合は「緊急停止」→「緊急停止する」で中止できます。直近の緊急停止日時は「設定」で確認できます。
6. キッチン認証から10分後、「起床確認：キッチンに移動してください」で再び鳴動します。同じキッチンQRを読むと音と振動が止まり、ここから5分間の待機が始まります。待機中は画面を閉じられます。
7. 「最終確認：洗面所に移動してください」で洗面所QRを読むと完了です。完了画面で初回鳴動、初回2地点認証、キッチン再認証、最終認証の時刻と所要時間を確認できます。

例えば06:03に初回のキッチンQRを読むと、次のアラームは06:13です。そこで06:14にキッチンQRを読んだ場合、最終アラームは06:19になります。各アラームの開始から60秒経過しても必要な認証が終わらない場合は、同じ段階で通知の文面を更新し、振動の間隔を短くします。初回の2地点は一つのアラーム段階として扱います。

### アラームカードの使い方

カードをタップすると編集画面が開きます。時刻・名前・音・振動は「保存」で確定し、「×」で編集を取り消せます。削除には別の確認画面があります。カード右端のスイッチでオン／オフを切り替えます。

| 設定・状況 | 動作 |
| --- | --- |
| 曜日を選ばない | 次にその時刻になる今日または明日に1回鳴り、鳴動開始時に自動でオフになります。カードは再利用できます。 |
| 月～日の丸ボタン | 選んだ曜日に繰り返します。最終QRで完了したとき、または緊急停止したときに、次の該当曜日を予約します。 |
| 初回の「5分スヌーズ」 | 最初の読み取りを開く前に1回だけ使えます。5分後は同じアラームの洗面所認証から再開します。10分・5分の起床確認は、それぞれ対応するQR認証を終えた時点から始まります。 |
| 時刻が重なったとき | 実行中のアラームがスヌーズ・QR認証・監視待機を終えるまで、後続を保留します。完了または緊急停止した後、期限を過ぎたカードを予定順に鳴らします。同時刻なら保存済みID順です。繰り返しカードの保留は1枚につき1回分です。各回で4回のQR認証が必要です。 |
| 再起動・時刻変更 | 有効なカードと進行中の段階からOSの次の予約を復元します。タイムゾーン変更後も各カードの現地時刻を使います。夏時間の欠落時刻は欠落幅だけ後にずらし、重複時刻は最初の1回を使います。 |

v0.2.2から同じ署名で上書きすると、以前の予約が1枚のカードになります。旧版で指定した将来の日付も初回予約に引き継ぎます。QRは全カードで共通です。起床確認の途中で更新した場合は、保存済みの段階と期限から続けます。

### 次回だけスキップする

オンになっている繰り返しカードを開き、「次回だけスキップ」の対象日時を確認してオンにし、「保存」を押します。例えば平日7時のアラームで木曜日をスキップすると、次は金曜日の7時に鳴ります。対象日時まではカードの「取消」で戻せます。同時刻にある別のカードは予定どおり鳴ります。

スキップはカードIDと予定日時の組で保存します。曜日・時刻の変更、オフへの切り替え、端末のタイムゾーン変更時は古い指定を解除します。通常の再起動では指定が残ります。スキップした回は履歴に追加されません。

### 起床履歴を読む

「履歴」タブで月を選ぶと、初回鳴動日の新しい順に表示します。完了した回に所要時間の記録があれば、月ごとの完了・緊急停止件数と完了回の平均所要時間も表示します。1回分をタップすると初回鳴動、洗面所 → キッチン → キッチン → 洗面所の各認証、終了時刻、所要時間、スヌーズ・無応答強化の回数を確認できます。名前は鳴り始めた時点で保存され、カードを編集・削除した後も残ります。

最終QRを読んだ直後に完了画面が開きます。「ホームへ」を押すかアプリを閉じると、次の通常起動はホームです。認証や待機がまだ続いている場合は、その段階に戻ります。

| 状態 | 記録の意味 |
| --- | --- |
| `IN_PROGRESS` | 認証中または待機中。済んだ段階まで表示します。 |
| `COMPLETED` | 最終の洗面所QRに成功し、完了時刻が確定しました。 |
| `EMERGENCY_STOPPED` | 緊急停止を実行しました。終了時刻までの経過時間が残ります。 |
| `INTERRUPTED` | 整合する進行状態を復元できなかった記録です。実際の終了時刻が不明な項目は空欄です。 |

進行状態と記録の更新は同じDataStoreトランザクションで確定します。終了した記録を端末内のSQLiteへ移し、保存後にDataStoreの転記待ちを解除します。途中でプロセスが終了しても、同じ記録IDで転記を再試行できます。v0.3.0からは同じ署名のAPKを上書きしてください。カード・QR・音設定を引き継ぎます。更新前に終了した回の履歴は作成しません。更新中に進行していた回は、旧版が保持していた時刻だけを引き継ぎます。

### CSVを書き出す

「履歴」→ 右上のダウンロードボタン（CSVエクスポート）で全期間・月指定・日付範囲から選び、「保存先を選ぶ」を押します。Androidのファイル選択画面で名前と保存先を指定します。範囲の両端を含め、各回の初回鳴動時の現地日付で抽出します。該当する回がない場合はヘッダーだけを書き出します。

| カラム（左から出力順） | 内容 |
| --- | --- |
| `record_id`, `alarm_id`, `alarm_name` | 1回の固定UUID、カードID、鳴動時の名前 |
| `scheduled_at`, `first_ring_at` | 予定日時、初回鳴動の処理開始日時 |
| `bathroom_1_at`, `kitchen_1_at`, `kitchen_2_at`, `bathroom_2_at` | 4回のQR認証成功日時 |
| `completed_at`, `ended_at` | 正常完了日時、完了または緊急停止の確定日時 |
| `duration_seconds` | 初回鳴動から確定した終了までの秒数。端末時刻の巻き戻しで負になる場合も空欄 |
| `snooze_count`, `escalation_count`, `status` | スヌーズ回数、無応答時の強化回数、上表の状態 |

UTF-8、カンマ区切りです。日時には記録時のタイムゾーンに基づくISO 8601のオフセットが付きます。未記録値は空欄です。名前のカンマ・改行・引用符をエスケープし、表計算で数式に解釈され得る名前の先頭にはアポストロフィを付けます。QRの値は出力しません。

**Obsidianへの取り込み**　Obsidianのコミュニティプラグイン「Importer」を有効にし、ImporterでCSVを選びます。書き出したファイルを開き、ノート名に `record_id`、必要な列をプロパティに指定して、プレビューを確認して取り込みます。期間を重ねて再出力した場合は同じ `record_id` で既存ノートと照合できます。[Obsidian公式のCSV取り込み手順](https://help.obsidian.md/import/csv)

### v0.4.0の実機確認手順

1. v0.3.0に登録済みのQR・音・カードを確認してから上書きし、同じ設定で起動することを確かめます。
2. 短時間テストで実際に4回読み取り、完了直後の画面と履歴の各時刻を照合します。完了画面でアプリを閉じて再度開き、ホームから同じ履歴へ移動します。
3. 別の回でスヌーズ・無応答の強化・緊急停止を試し、履歴の回数・状態を確認します。待機中はアプリを閉じ、再起動後も同じ回が続くことを確かめます。
4. 同時刻の繰り返しカードを2枚用意し、片方の次回だけをスキップします。端末再起動後の表示、取り消した場合の予約、スキップした場合のもう片方の鳴動と次回の復帰を確かめます。
5. CSVを全期間・月・日付範囲で保存し、保存キャンセルも試します。日付境界、改行や引用符を含む名前、未完了回の空欄、Obsidianのプレビューを確認します。

### アラーム音・音量の設定

- カードの「アラーム音」を開くと、現在の選択名が表示されます。初期値は「端末のデフォルト」です。「端末のアラーム音から選ぶ」でOSの登録音を選択できます。標準ピッカーを開けない場合はアプリ内に登録音の一覧を表示します。[RingtoneManager](https://developer.android.com/reference/android/media/RingtoneManager)
- 「音声ファイルから選ぶ」で端末内のMP3・M4A・WAVなどを指定できます。再生できる形式は端末のデコーダーに依存します。アプリは選んだファイルの読み取り権限を保持し、別の音に変更すると不要になった権限を解放します。[Androidのファイル選択](https://developer.android.com/training/data-storage/shared/documents-files)
- 「試聴」で現在のアラーム音量で再生し、「停止」で止めます。音源変更、別画面への移動、バックグラウンド移行でも試聴は止まります。初回・キッチン再確認・最終洗面所確認の3段階すべてに同じ選択が適用されます。
- ファイル削除・アクセス喪失・デコード失敗時は端末のデフォルト音を試し、それも再生できない場合は同梱音を使います。「端末のデフォルトに戻す」で選択をリセットできます。
- **この設定は端末全体のアラーム音量に反映されます。** スライダーの0〜100%は、端末が選べる最小〜最大の段階に対応します。最小音量が正の端末では0%でも音が出ることがあります。音量は操作を確定したときにだけOSに書き込み、次に画面を開いたときにはOSから読み直します。音量固定・変更拒否の場合は画面に案内が出ます。

### 短時間で試す（デバッグAPK）

アラーム一覧ですべての予約をオフにし、「設定」の「短時間テスト」をオンにしてから日時を設定します。ホームに「短時間テスト中」と表示されます。通常運用に戻すときは、完了または緊急停止後、次の予約を入れる前にスイッチをオフにします。

| タイミング | 通常 | 短時間 |
| --- | --- | --- |
| 初回鳴動 | 設定日時 | 設定日時 |
| キッチン再認証 | 初回認証の10分後 | 30秒後 |
| 最終洗面所認証 | 再認証の5分後 | 20秒後 |
| 無応答時の振動強化 | 各アラーム開始の60秒後 | 15秒後 |

初期値は通常です。予約済み・実行中はモードを固定し、リリース版では短時間モードを利用できません。

## 状態と保存

```text
IDLE → INITIAL_ALARM → AWAITING_BATHROOM_QR → AWAITING_KITCHEN_QR
     → WAITING_FIRST_CHALLENGE → FIRST_CHALLENGE_ACTIVE（キッチン）
     → WAITING_FINAL_CHALLENGE → FINAL_CHALLENGE_ACTIVE（洗面所）→ COMPLETED
INITIAL_ALARM → SNOOZED → INITIAL_ALARM（初回のみ）
実行中・待機中 → EMERGENCY_STOPPED（確認付き緊急停止）
```

`Protocol.kt` に状態遷移とQR検証をまとめ、`WakeStore.kt` が予定日時・有効フラグ・段階・期限・結果・地点別トークンをPreferences DataStoreにまとめて保存します。`WakeViewModel.kt` を介してComposeに反映します。カメラ映像は保存しません。トークンの入力形式は `wakelock:v1:<地点>:<URL-safe文字22個>` で、地点・順番・トークン全文を照合します。

アプリ専用領域に保存し、OSバックアップを無効化しています。コピーした同一のQRは同じ地点として認証されます。地点名は洗面所が `bathroom`、キッチンが `kitchen` です。個人用QRはリポジトリの外に保管し、リポジトリ内の `qrcodes/` もGitの対象から除外しています。登録済みトークンを差し替えるときは、実行中の起床確認を終えてから登録画面で変更します。

### QRコードの保存・共有・印刷

| やりたいこと | QRコード管理での操作 |
| --- | --- |
| 初めて発行する | 未登録地点の「QRを作成」を押します。端末の `SecureRandom` が生成した16バイトをURL-safe Base64の22文字（パディングなし）に変換し、その地点に登録します。 |
| 同じQRをもう一枚用意する | 登録済み地点の「表示・印刷」を押します。Python版で登録した場合も、保存済みトークンから元の文字列を復元します。表示・保存・印刷でトークンは変わりません。 |
| PNGを保存する | 画像の下の「PNGで保存」で保存先を選びます。ファイル名の初期値は `bathroom.png` または `kitchen.png` です。保存先のアプリがクラウドに同期する場合があります。 |
| 他のアプリに渡す | 「共有」から送り先を選びます。読み取り用URIでPNGを渡し、一時ファイルはアプリ専用キャッシュに置きます。作成後24時間を過ぎた一時ファイルは次にアプリを起動してQR管理を開いたとき、または次の共有時に削除します。 |
| 印刷する | 「A4で印刷」でAndroidの印刷画面を開き、用紙と出力先を選びます。初期設定はA4、1地点1ページです。QR本体は約5cmで、周囲に4モジュールの白い余白があります。地点名とファイル名を含む外枠に沿って裁断します。プリンターを利用できない場合はPNGを保存して別端末で印刷できます。 |
| 紛失したQRを無効にする | 地点の「再発行」で対象を確認し、「再発行する」で確定します。以降は旧QRとそのコピーが失効するので、新しい画像を印刷して貼り替えます。「キャンセル」で今のQRを使い続けられます。 |

画像や印刷物を受け取った人は同じ認証情報を複製できます。保存先・共有先・プリンターは自分で管理できるものを選んでください。起床プロトコル中は、10分と5分の監視待機中も登録変更がロックされます。

### 旧版から更新する場合

同じ署名のAPKを上書きすると、既存のDataStoreから2地点のトークン、設定日時、直近の緊急停止日時を引き継ぎます。旧版で有効だった未実行予約はv2の初回アラームとして復元します。旧版の実行途中または不整合がある記録は `RECOVERY_REQUIRED` とし、ホームのカードのスイッチから再予約できます。旧版のボタンによる完了はv2の認証実績に算入しません。旧形式の予約を取り消し、遅れて届いた旧形式の配信も無視します。

## Androidの権限と予約の動作

| 権限・機能 | 動作 |
| --- | --- |
| 正確なアラーム | Android 12以降は `SCHEDULE_EXACT_ALARM` と `canScheduleExactAlarms()` を確認。許可後のブロードキャストとアプリ再開時に保存済み状態から予約します。 |
| 通知 | Android 13以降は `POST_NOTIFICATIONS` を許可してください。アラーム鳴動・起床の再確認・鳴動できない時の通知の各チャネルは、OSの通知設定で個別に変更できます。 |
| 全画面通知 | `USE_FULL_SCREEN_INTENT` を宣言し、Android 14以降は `canUseFullScreenIntent()` を確認します。使用できない場合は高重要度の通知から画面を開けます。表示形式はOSとチャネル設定によります。 |
| カメラ | QR読み取り画面が表示されている間に背面カメラを利用します。拒否後はアプリ権限設定へ移動できます。 |
| 鳴動 | `mediaPlayback` 型のフォアグラウンドサービスが `USAGE_ALARM` で音源をループ再生し、端末が対応していれば振動します。サービス開始が制限された場合は代替通知を試みます。 |
| 再起動・スリープ | `RECEIVE_BOOT_COMPLETED` で再起動後の初回ロック解除後に予約を復元します。受信処理と再生に `WAKE_LOCK`、振動に `VIBRATE` を使います。 |

`WakeApp.kt` は次の鳴動または無応答時の強化のうち、必要な予約1件を `AlarmManager.setAlarmClock()` で置き換えます。配信時には予約の世代、段階、期限を保存値と照合します。カメラの結果も、その読み取りを開いた世代と段階に結びつけます。完了・緊急停止時はこの回の通知を消し、次に有効なカードへOS予約を切り替えます。[正確なアラーム](https://developer.android.com/develop/background-work/services/alarms/schedule) ／ [Doze](https://developer.android.com/training/monitoring-device-state/doze-standby)

BroadcastReceiverは短い復元・配信処理を行い、ユーザーが予約したアラームの配信時に再生サービスを起動します。再起動ブロードキャストからは予約の復元を行います。Android 15以降では再起動受信時のメディア再生サービス直接起動が制限されます。[ブロードキャスト](https://developer.android.com/develop/background-work/background-tasks/broadcasts) ／ [バックグラウンド起動制限](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start) ／ [サービス種別](https://developer.android.com/develop/background-work/services/fgs/service-types)

全画面表示や通知表示の可否は端末設定に従います。Android 17の音声制御にも配慮し、アラーム音量の強制変更は行いません。[通知権限](https://developer.android.com/develop/ui/views/notifications/notification-permission) ／ [全画面通知の制限](https://developer.android.com/about/versions/14/behavior-changes-14) ／ [Android 17の音声制御](https://developer.android.com/about/versions/17/changes/bg-audio)

再生サービスをフォアグラウンドにしてからアラーム用の一時的なAudio Focusを要求します。一時的にフォーカスを失った場合は音声を中断し、再取得時に再生します。振動の強化でプレーヤーを追加することはありません。[Audio Focus](https://developer.android.com/media/optimize/audio-focus)

## 既知の制限

- 電源断中、再起動後の初回ロック解除前、設定画面からの強制停止中は通知できません。強制停止後は手動でアプリを開いてください。すでに期限を過ぎていた予約は、復元できた時点で処理します。
- 正確なアラーム権限の剥奪でOS予約が取り消されます。通知拒否・通知チャネルの無効化・Xiaomi HyperOSなどのメーカー独自の省電力設定により、再確認が見えない、鳴動や復帰が遅れる場合があります。ロック画面からカメラを使う際に端末のロック解除が必要なこともあります。
- 進行中のQR確認とスヌーズの期限は端末時計の絶対時刻で保存します。手動で時計を進める・戻すと再確認までの実時間も変わり得ます。
- 進行中の起床確認は1件です。起床履歴は端末内に保存します。アプリをアンインストールすると履歴も消えるので、残したい記録はCSVに書き出してください。クラウドへの自動保存には対応していません。
